# moo

A small code generator that adds Moo-style ergonomics to Go structs:
functional options, defaults, validation, `Clone()`, and `String()`.

Unlike Moo for Perl, `moo` does **not** use reflection at runtime. It reads
your struct tags at build time and emits plain, idiomatic Go that GoLand
(and every other Go tool) can see, autocomplete, refactor, and navigate.

## Install

```bash
go install github.com/thomas666-beast/moo/cmd/moo@latest
```

## Usage

Annotate a struct with `moo:` tags:

```go
package models

//go:generate moo point.go

type Point struct {
    X    int      `moo:"default=0"`
    Y    int      `moo:"default=0;required"`
    Name string   `moo:"default=\"origin\";min=1;max=64"`
    Tags []string `moo:""`
    ID   int64    `moo:"readonly"`
}
```

Then run:

```bash
go generate ./...
# or, for a single file:
moo models/point.go
```

`moo` writes `zz_moo_point.go` next to the source. That file is ordinary Go
and should be committed.

## What gets generated

For each struct `Point` that has at least one `moo:`-tagged field:

- `type PointOption func(*Point)` — functional-option type
- `WithX(v T) PointOption` — one per writable field
- `NewPoint(opts ...PointOption) (*Point, error)` — applies defaults, then
  options, then calls `Validate()`
- `Validate() error` — checks all declared invariants
- `Clone() *Point` — shallow copy, with slices and maps duplicated
- `String() string` — readable representation

## Tag grammar

Tags are a `;`-separated list of `key` or `key=value` items:

| Key        | Value         | Meaning                                                     |
|------------|---------------|-------------------------------------------------------------|
| `-`        | (alone)       | Skip the field entirely (no option, no validation)          |
| `readonly` | —             | No `WithX` option; still validated and cloned               |
| `required` | —             | Must be non-zero / non-nil / non-empty                      |
| `default`  | Go expr       | Initial value in `NewX`. The expression is emitted verbatim |
| `min`      | integer       | Numeric: `>=`. String/slice/map: length `>=`                |
| `max`      | integer       | Numeric: `<=`. String/slice/map: length `<=`                |
| `enum`     | `a\|b\|c`     | Allowed set; only checked when value is non-empty           |
| `match`    | `email`       | Only checked when value is non-empty                        |

Multiple keys combine: `moo:"required;min=1;max=64"`.

## Semantics

- `required` and `min`/`max` are **always** checked.
- `enum` and `match` are only checked **when the value is non-empty**.
  Combine with `required` if you want "must be set and must be valid":
  `moo:"required;match=email"`.
- Fields without a `moo:` tag are writable and unvalidated but still cloned
  and printed.
- Unexported fields are skipped for options (you can't set them from outside
  the package) but still included in `Clone` and `String`.

## Example output

For the `Point` struct above, `moo` generates:

```go
// Code generated by moo. DO NOT EDIT.

package models

import (
    "fmt"
    "strings"
)

type PointOption func(*Point)

func WithX(v int) PointOption {
    return func(x *Point) { x.X = v }
}

func WithY(v int) PointOption {
    return func(x *Point) { x.Y = v }
}

func WithName(v string) PointOption {
    return func(x *Point) { x.Name = v }
}

func WithTags(v []string) PointOption {
    return func(x *Point) { x.Tags = v }
}

func NewPoint(opts ...PointOption) (*Point, error) {
    x := &Point{
        X:    0,
        Y:    0,
        Name: "origin",
    }
    for _, opt := range opts {
        opt(x)
    }
    if err := x.Validate(); err != nil {
        return nil, err
    }
    return x, nil
}

func (x *Point) Validate() error {
    if x.Y == 0 {
        return fmt.Errorf("Y is required")
    }
    if len(x.Name) < 1 {
        return fmt.Errorf("Name length must be >= 1")
    }
    if len(x.Name) > 64 {
        return fmt.Errorf("Name length must be <= 64")
    }
    return nil
}

func (x *Point) Clone() *Point {
    if x == nil {
        return nil
    }
    c := *x
    if x.Tags != nil {
        c.Tags = append([]string(nil), x.Tags...)
    }
    return &c
}

func (x *Point) String() string {
    if x == nil {
        return "Point(nil)"
    }
    var b strings.Builder
    b.WriteString("Point{")
    b.WriteString("X: ")
    fmt.Fprintf(&b, "%v", x.X)
    b.WriteString(", ")
    b.WriteString("Y: ")
    fmt.Fprintf(&b, "%v", x.Y)
    b.WriteString(", ")
    b.WriteString("Name: ")
    fmt.Fprintf(&b, "%q", x.Name)
    b.WriteString(", ")
    b.WriteString("Tags: ")
    fmt.Fprintf(&b, "%v", x.Tags)
    b.WriteString("}")
    return b.String()
}
```

## Layout

```
cmd/moo/             CLI entry
internal/model/      IR types (StructSpec, FieldSpec)
internal/tag/        tag grammar parser
internal/parser/     Go AST → IR
internal/gen/        IR → Go source, with golden tests
e2e/                 end-to-end package that uses generated code
```

## Development

```bash
go test ./...
go install ./cmd/moo && go generate ./...
```

If `go generate ./...` leaves `git status` dirty, your checked-in generated
files are stale. Regenerate and commit.

## Limitations

- `enum` currently only meaningful for `string` fields.
- `Clone` deep-copies slices and maps, but not pointers or nested slices.
- `String` uses `%q` for strings and `%v` otherwise; no JSON.
- No support for embedded structs yet.
- No roles/interfaces beyond plain Go interfaces.

## Notes

- The enum row uses a\|b\|c — the backslashes are required in a Markdown table cell so the pipe isn't parsed as a column separator.

- The generated-code example uses "fmt" and "strings" imports. Your golden/e2e output already matches this shape; the example is illustrative, not byte-identical to any specific file.
